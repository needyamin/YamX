Overview

yamx is the coding REPL. It opens with no model, runs shell commands on this machine, and uses a connected model only when you ask it to change or debug code.

Starts offline

The welcome card shows the folder, local · offline, the session, and v1.0.30. Canceling setup does not exit.

Facts before code

Every write, fix, or debug turn records path, OS, scripts, git state, and files named in the error before the model speaks.

A crew, not one guess

Explorers and the reviewer read in parallel. One implementer or debugger writes, then the same test is allowed to run again.

Any chat API

Base URL, API key, and any model name. Stored as providers.custom.

Start

npm install -g @needyamin/yamx@latest
yamx

From this repository:

npm install
npm run build
node dist/index.js

A pixel YamX mark plays, then the card. The prompt is >. Type git status or /help. On Windows, ip runs as ipconfig. Dangerous commands still ask first.

Coding architecture

Greetings and bare shell lines stay local. A coding ask always builds a project brief on disk, with no model call.

User turn Local project brief No model: save brief, ask /connect Parent agent Read, grep, edit, shell delegate Explorer, in parallel Debugger writes, then reruns Reviewer reads the diff Verify

The brief includes:

  • Absolute project path and working directory
  • OS and shell
  • Package manager and the test, lint, and build scripts that exist
  • Git branch and whether the tree is dirty
  • Entry files and any files named in the error you pasted

That text is the first context for the parent and for every sub-agent. They still re-read a file before editing it. After a real edit, the same test command may run again. An unchanged rerun is skipped.

Sub-agents

RoleWork
explorerRead, grep, and map. Runs together with other explorers and the reviewer.
implementerReads, then edit_file, multi_edit, patch_file, or write_file.
debuggerReproduces the failure, edits, and reruns that command.
reviewerReads git status and git diff. Does not edit.
plannerRead-only plan. Used by /plan.

Writers run one at a time and lock the paths they name. Each child returns files changed, commands, the first error, and whether verify passed. The parent does not redo the edits. Up to 3 readers run at once (settings.subagents.maxParallel). A child stops after 12 iterations (settings.subagents.maxIterations).

In the terminal a child looks like ● Explore or ● Debug, with its tool lines nested underneath.

33 tools

  • Files: read_file, read_files, write_file, write_files, edit_file, list_files, search_files, delete_file
  • Edits and search: multi_edit, patch_file, grep_search, directory_tree, find_references, copy_file, move_file, file_info
  • Shell: run_command, run_command_background, shell_diagnostics, task_list, task_tail, task_stop
  • Git: git_status, git_diff, git_commit, git_log, git_branch, git_stash
  • Intel: project_intel, codebase_analysis, log_inspect, fetch_url
  • Crew: delegate

Deletes and destructive shell commands still ask for approval. Several reads in one reply run together. Writes and shell commands stay in order.

Connect a model

/connect, yamx --onboard, and the web Settings → Model page ask for the same fields.

Base URL    https://api.example.com/v1
API key     sk-...
Model name  my-model

YamX keeps the base URL, API key, model name, and optional extra headers in ~/.yamx/config.json under providers.custom. Leave the key blank later to keep the saved key. A local server can omit the key.

Environment overrides: YAMX_CUSTOM_BASE_URL, YAMX_CUSTOM_API_KEY, YAMX_CUSTOM_MODEL. An older config that names another provider does not start that model.

Web

yamx web
yamx web --host 127.0.0.1 --port 8765

The server binds to loopback. Chat, sessions, and config are on the page. Saving settings does not drop providers.custom.

Config

~/.yamx/config.json holds providers and settings. Sessions are in ~/.yamx/sessions/. Coding limits live under settings.subagents. permissionMode can be default, ask, read-only, or auto-safe.

ymax, the offline router

ymax is a separate binary. It sends one request to a local expert and does not open the coding REPL. It needs no API key.

ymax "git status"
ymax "read package.json"
ymax help

Experts: general, filesystem, shell, git, devops, security, project, web. Use yamx when the job is to write, fix, or debug a repository.
